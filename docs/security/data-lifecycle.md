# Data lifecycle

Four behaviors are separate. None of them stands in for the others.

1. **Governed-memory deletion.** Logical delete, then physical purge of the memory, its revisions, and its events. The tombstone has no content. Search and later context assembly do not return the memory.
2. **Derived-context redaction.** A limited edit of `context_records` during that purge.
3. **Operational audit retention.** Task, plan, approval, execution, goal, and invocation rows stay so authorization and execution can still be explained.
4. **Infrastructure retention.** Backups, WAL, and snapshots are outside this process.

## Categories

| --- | --- | --- | --- | --- | --- | --- | --- |

A table is not harmless because its name is not `memories`. `tasks.request_text`, approval payloads, and execution inputs are user or derived text. Purge does not delete them. A deleted memory can still be read from those rows. This document does not claim that reconstruction is impossible.

## Governed memory

`DELETE /v1/memory/{id}` sets `lifecycle` to `deleted`. Search and `POST /v1/memory/context` skip that row. `POST /v1/memory/purge` and the worker remove a deleted row whose `deleted_at` is older than `APEX_MEMORY_PURGE_AFTER_HOURS`. Revisions and events for that id go with it. `memory_purges` stores the id, scope, revision count, and time. Running purge again does not remove the tombstone and does not return the memory. The same result is visible through a new database connection.

An active or completed goal does not block that purge. The goal row remains. Invocation input keeps memory ids and does not keep the memory body.

## Derived context

Redaction runs on `context_records.content` for each purged memory. The deleted string and the stored text are compared after Unicode case folding and after collapsing each whitespace run to one space. A match requires at least 12 characters in that normalized form, including a string whose original length is shorter because one character casefolds to several. The matched original span, including the original case, spacing, and the source characters that expanded, is replaced with `[redacted]`. Surrounding text outside that span stays. The row stays.

This does not match:

- a secret whose normalized form is shorter than 12 characters, even if case folding changed it
- a paraphrase
- a hash or other encoding of the secret
- a suffix or prefix that is not the whole secret
- text that merely means the same thing

Case differences, casefold expansions such as `ß` to `ss` and `ﬃ` to `ffi`, and extra spaces between the same characters do match. The replacement is the original span, not an offset calculated in the expanded string.

## Operational audit

`APEX_OPERATIONAL_RETENTION_DAYS` defaults to 0. Zero means Apex does not expire operational rows.

When the value is positive, the worker deletes `context_records` whose `trust` is `proposal`, whose `created_at` is older than that many days, and whose `scope_id` is not an unresolved task id, an unresolved goal id, or the task id of an unresolved goal. Unresolved means the row is not `completed`, `failed`, or `cancelled` for a task, and not `completed`, `partial`, `failed`, or `cancelled` for a goal. `uncertain`, `awaiting_approval`, `planned`, and `running` stay unresolved. It does not delete:

- `trust` `trusted` context rows
- tasks, task events, plans, plan steps, or plan revisions
- approvals
- executions or verifications
- goals, subtasks, invocations, or goal events

Those rows are how an operator checks who approved an operation, what was executed, and which uncertain outcome is still unresolved. Deleting them would make the authority record weaker. A proposal tied to unresolved work stays until that work is terminal. An old proposal with no such association, including one whose work has reached a terminal state, can expire. Running expiry again removes nothing further. Proposal expiry does not run for a row that is an approval, an execution, or a goal, because those are not context proposals.

## Connections

Connection rows store an endpoint, a secret reference, scopes, and state. They do not store secret values or pairing codes. The pairing code is returned once and only its hash is kept. Revocation sets state and disables capabilities. It does not delete the connection, device, execution, or approval rows. The reference inventory and device are process memory. They are not governed memory and they are not included in a provider request. This does not erase a remote MCP server's logs.

## Temporary media

Raw image and audio bytes are files, not database columns and not governed memory. The default lifetime is the request. `APEX_MEDIA_CONVERSATION_RETENTION` must be true and the turn must set `retain_media` before a file is kept for the conversation. Kept files expire after `APEX_MEDIA_TTL_SECONDS` (default 3600, maximum 86400). Deletion sets `deleted_at` and removes the file. A later reference is `media_unavailable` or `not_found`.

`media_objects` keeps the digest, size, media type, provenance, and trust. `interactions.request_json` stores media ids, not bytes. `interactions.response_json` stores normalized text, transcript text, and generated-audio ids. A transcript is derived. Model text is advisory. Neither is written to `memories` by the interaction service.

Logs may include the interaction id, provider, model, modality names, byte count, latency, and outcome. They do not include the file, the prompt, or a provider payload. There is no unauthenticated media route and no fetch of a caller-supplied URL.

This process can delete its temporary file. It cannot delete a copy a provider retained after a call, and it cannot delete backups or WAL. Those remain operator and provider retention.

## Infrastructure

Apex cannot delete a row from an immutable backup, a base backup, a WAL archive, or a snapshot taken outside this database. `APEX_BACKUP_RETENTION_DAYS` records the retention the operator is expected to apply. It does not expire a backup. Erasure from those copies is an operator and infrastructure action, and this repository does not verify it.
